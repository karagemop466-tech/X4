# `data/ops/` - the operating layer (T21)

Everything in this directory is generated by the tools in `tools/` (T21) or fetched
verbatim from a named upstream. Nothing here is typed in by hand.

| File | Written by | What it is |
|---|---|---|
| `markets.csv` | `tools/origination.py` | Every market we originate: one row per game per market type, in the mandated order (side, total, moneyline) |
| `price_snapshots.csv` | `tools/fetch.py` + `tools/origination.py` | **The price-snapshot store.** One row per (event, market, book, snapshot kind). Carries `open_*` and `close_*` numbers as separate columns, with the snapshot timestamp and the retrieval URL |
| `raw/*.json` | `tools/fetch.py` | The verbatim response bodies. Never edited |
| `snapshots.csv` | `tools/fetch.py` | The provenance manifest: url, file, sha256, bytes, UTC retrieval time, HTTP result |
| `results.csv` | `tools/origination.py` | The verified results feed: final score for every event, with the official NFL.com game URL |
| `graded.csv` | `tools/origination.py` | Every originated market graded against `results.csv` |
| `scores_signal.csv` | `tools/origination.py` | Signal score per strategy (skill evidence) |
| `scores_staking.csv` | `tools/origination.py` | Staking score per strategy (paper money), kept deliberately separate |
| `depth.csv` | `tools/origination.py` | Replacement-depth ledger: who was lost, how deep the replacement is, and the evidence |
| `paper_demotions.csv` | `tools/origination.py` | The demotion gate log: every live -> paper transition with the rule that fired |

## The five rules this store obeys

1. **Open and close are separate columns.** A single "line" column is not allowed:
   `open_*` is the number recorded at the first snapshot of that market, `close_*` is the
   number recorded at the last snapshot before the event started. If only one snapshot
   exists, `close_*` is copied and `close_kind` says `same_as_open`, so nobody mistakes
   a single reading for a movement.
2. **Nothing is overwritten.** A re-fetch appends a new snapshot row; it never edits an
   existing one. The file therefore grows and the history is the audit trail.
3. **Every row carries provenance.** `retrieved_utc` and `source_url` are mandatory. A row
   with an empty `source_url` is a build error, not a blank.
4. **A missing number stays blank.** No interpolation, no "last known value", no carry
   forward. Blank means the upstream did not publish it at that snapshot.
5. **Third-party prices are labelled as such.** Prices are a commercial product. They are
   stored with `tier` = `T3` (third-party publisher) unless a licensed feed is authorised
   later. This is the same convention the desk layer already uses for its Week 11 snapshot.
