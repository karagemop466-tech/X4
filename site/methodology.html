10 · How it works

Methodology

Everything on this site is produced by scripts from the CSV files in data/. Nothing is hand-typed into a page at publish time, and every table is written into the HTML at build time, so the pages work with JavaScript disabled.

Reproducible
Step 1 · Acquire

Official pages only

The official NFL.com standings, the official weekly injury report and the official weekly schedule are the source of record. Secondary aggregators were used to reconstruct the game log, and every reconstructed score is then proved against the official standings totals - a single wrong score changes a team's points for or points allowed, so matching all 32 teams on all six measures proves every score.

Step 2 · Verify

tools/verify.py

460 assertions covering: every game row's official URL pattern, every team's wins, losses, ties, points for, points allowed, net points and winning percentage, games played per team, the Week 11 schedule's pairing and URL structure, and duplicate rows. It exits non-zero on any failure and runs as part of the build.

Step 3 · Model

Opponent-adjusted rates

For a team, the opponent-adjusted points-for rate is the team's own scoring rate minus the average points allowed by the opponents it has faced, plus the league average. The same construction gives the opponent-adjusted points-allowed rate. A team's expected score is the mean of its adjusted offence and its opponent's adjusted defence, with the league home-field margin added. Every quantity used for a Week-w forecast is measured strictly from games before Week w, including the opponents' season rates, so there is no look-ahead.

Step 4 · Validate

Walk-forward, seven gates

Strategies are evaluated only on games that had not been played at forecast time - no random row splits. Each strategy must clear data integrity, out-of-sample discipline, minimum sample size, statistical significance, weekly stability, calibration, and exclusion of the league-constant benchmark, before it can earn reward points.

Frozen policies

Two decisions fixed before any backtest is published

Both policies below were frozen on 2026-11-17, before any backtest on the reconstructed game log has been published. A policy frozen after results are seen is not a policy; these two are registered here, in the build that publishes the numbers they govern.

Price-data policyEvery captured price is third-party (DraftKings as syndicated by the public ESPN odds endpoint), labelled T3, and never presented as an official NFL line. CLV and any staking claim stay blocked until a licensed, timestamped operator feed with a documented backfill and settlement policy is selected. Reproduce it

Running the pipeline

From a clean checkout:
python3 tools/verify.py  - proves the data against the official standings
python3 tools/build.py  - rebuilds every published number into data/output/
python3 tools/pages.py  - regenerates the site pages as static HTML
python3 tools/sync.py  - mirrors the site to the repository root
python3 site/check.py  - checks the site for broken links and unsourced rows
python3 tools/validate.py  - runs the full publication gate

The build is deterministic: the same inputs produce the same tables and the same confidence intervals on every run, and every table is written into the HTML so no published value depends on JavaScript.
