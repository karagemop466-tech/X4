What this layer is

Every number on the Game books page is derived from an official NFL Game Book: the PDF the league publishes after each game holding the lineups, the substitutions, the did-not-play and not-active lists, and the header with the stadium, surface and weather. This page is the record of the layer underneath those numbers - the verbatim captures, their hashes and stamps, the parse that turns them into rows, and the reuse gate that separates what is stored from what is published.

The split is not ceremony. A PDF is a licensed artefact rather than data, so its text is kept as evidence that can be re-read and re-checked, and only values derived from it - a play rate with its interval, a starter row, a venue string - are published. The distinction matters most where the source is incomplete: a cell the conversion lost is published as a blank with the reason it is blank, and the raw capture is what lets a reader confirm that the blank is the source’s, not ours.

Pipeline

From a PDF link to a published number

Seven stages, each with the artefact it produces. Nothing enters a published dataset without passing through all seven.

StageWhat happensArtefact
1. LocateThe game-centre page of each official Week 10 game is read and the “Download Game Book (PDF)” link under END GAME is taken from that page.nfl.com/games/&lt;away&gt;-at-&lt;home&gt;-2026-reg-10
2. CaptureThe PDF is converted to text and stored verbatim under data/ops/raw/ with a UTC stamp. No value is edited at this stage.data/ops/raw/gamebook-*.txt
3. HashA SHA-256 is taken of every capture and recorded in the inventory, so a later edit is detectable rather than invisible.data/ops/gamebook-capture-inventory.json
4. ParseSections are split on the printed rule lines and each of the four player lists - Lineups, Substitutions, Did Not Play, Not Active - is parsed into rows. A row the conversion lost is kept as a blank row with a flag.tools/gamebook_sweep.py
5. JoinEach player on the official Week 10 injury report is matched to his own game’s Game Book by surname and first initial. A surname alone is not accepted.tools/gamebook_sweep.py
6. DerivePlay rates are computed per designation with a 95% Wilson interval and the unresolved count published beside n.data/designation-reliability-wk10-2026.csv
7. PublishOnly the derived datasets reach the site. The raw captures stay in the repository as evidence behind the private page.gamebook.html

Reuse gate

What this layer is deliberately not used for

The gate is the point of the layer. Each row is a way the data could be used that would produce a number the sources do not support.

Not used forWhy
Re-publishing the PDF textThe Game Book is a licensed league artefact. Its verbatim text is evidence, not content, so it is stored and hashed rather than rendered as a page of its own.
Filling a blank by inferenceWhere the conversion lost a cell - eleven Cleveland starters, a Dallas defensive name column - the cell is published blank with the reason. It is never filled from another week, a club site or a memory of the roster.
Deciding a designation outcome from absenceA player absent from all four Game Book sections is unresolved, not &lsquo;did not play&rsquo;. Treating absence as an inactive would inflate n and bias the play rate downward.
Feeding the calibration into the modelOne week of one season is a first estimate, not a constant. The Doubtful interval spans 3%&ndash;56%, so it is published as uninformative rather than used as a feature.
Ranking depth by jersey numberExplicitly rejected in the brief. Depth order comes from a club chart or from playing time, never from a number on a shirt.
Reproducing it

How to check this yourself

The sweep is one command and it validates before it writes. The gate enforces 14 games, an https source on every row, eleven-or-blank starters per unit, and the arithmetic of the reliability table.

python3 tools/gamebook_sweep.py --check    # validate only, exit 1 on any problem
python3 tools/gamebook_sweep.py            # rebuild the five datasets
sha256sum data/ops/raw/gamebook-*.txt      # compare with the register above
