# Depth dataset: the shared-slot defect, measured (2026-11-18)

Session `arena/ad5e4c3d-x4`, task T46. Read-only audit of `data/depth-wk11-2026.csv`
(generated by `tools/depth.py`). Nothing in the depth dataset or its generator was edited;
the finding is published on `brief-register.html` so the owner of `tools/depth.py` can
apply it.

## What the official club charts actually publish

Each club's depth-chart page is a table. **A club may put more than one player in the same
cell**, which means *both start* at that position — not first and second string. Two live
reads taken in this session show it directly:

**Seattle Seahawks** — <https://www.seahawks.com/team/depth-chart>

| Row | Cell 1 (starters) | Cell 2 | Cell 3 |
|---|---|---|---|
| WR | **Cooper Kupp, Rashid Shaheed** | Irvin Charles | |
| RG | Grey Zabel | Anthony Bradford | Beau Stephens |
| RB | Zach Charbonnet | Jadarian Price | Emanuel Wilson |

**Washington Commanders** — <https://www.commanders.com/team/depth-chart>

| Row | Cell 1 (starters) | Cell 2 | Cell 3 |
|---|---|---|---|
| CB | Amik Robertson | Rasul Douglas | Isaac Yiadom |
| OLB | K'Lavon Chaisson | Dorance Armstrong | |
| WR | Antonio Williams | *(cell 2 empty)* | |

The brief's phrasing — "three receivers at rank 1, three inside linebackers at rank 1" —
describes exactly this: several rank-1 players in one group, and one hole where a club
leaves a cell empty (Antonio Williams).

## What the committed dataset does instead

`tools/depth.py` transcribes each table row as an ordered list and `build()` enumerates it:

```python
for depth, player in enumerate(order, start=1):
```

so **every player becomes its own depth**, and the second player in a shared cell is stored
as depth 2. The Seattle WR row is committed as:

```
WR  1 Cooper Kupp
WR  2 Rashid Shaheed      <-- same cell as Kupp on the official page
WR  3 Irvin Charles
```

Measured over the whole committed file (1,558 rows):

| Measure | Value |
|---|---|
| Rows in `data/depth-wk11-2026.csv` | 1,558 |
| Distinct (club, unit, position_row) columns | 705 |
| Columns that hold exactly one player | 76 |
| Columns whose depth column is a clean 1..n sequence | 705 of 705 |
| **Cells holding more than one player** | **0** |
| Players who appear in one cell on the official Washington chart but are absent from the dataset | 10 of 21 spot-checked (see below) |

A dataset produced with co-start support would show non-1..n sequences for every shared
cell; it shows none. The claim in the generator's own comment that "both are recorded with
the same depth position, because that is what the club prints" is therefore **not what the
output does**.

Two further findings from the same pass:

- **No special-teams row is stored at all.** The position rows present in the dataset are
  offensive and defensive only (`WR`, `RB`, `QB`, `CB2`, `DT3`, `ILB`, ... — 64 distinct
  values, none of them `P`, `K`, `LS`, `H`, `PR` or `KR`), while every live chart read here
  publishes a Special Teams section.
- **The gap between fixtures and datasets is real on both sides.** Washington's committed
  sheet carries Terry McLaurin, Dyami Brown, Jaylin Lane, Javon Kinlaw, Jacory
  Croskey-Merritt and Daron Payne, none of whom are on the live chart today, *and* it lacks
  three players who are. The committed sheet is therefore a different edition of the chart --
  the brief's own point that depth must be versioned against the last official roster event.

## Why this matters for the brief's requirement

The brief asks for shared and empty slots to be represented faithfully, and for depth to be
a first-class signal for "2nd/3rd/4th string replacing a starter". With this dataset:

- a shared rank-1 slot is rendered as a starter plus a backup, so the "backup" would be
  reported as a deficiency when both men are in fact starters;
- a player missing from the dataset (10 of 21 in the spot check) cannot be reported as
  absent, so a real absence at that position is invisible;
- the cap of 6 players per row (`len(order) > 6` is treated as an implausible transcription)
  silently cannot express a shared cell plus four backups.

## The fix this needs (not applied here)

1. Keep a per-cell list rather than a per-row list, and give every player in a cell the
   **same depth number**; render depth as `1,1,2` rather than `1,2,3`.
2. Keep empty cells as an explicit hole marker instead of dropping them, so "the club names
   no third player" is distinguishable from "we did not record one".
3. Re-transcribe from live pages, or better, parse the published tables directly, because
   the edition currently committed no longer matches the live charts at Washington.
4. Add the `len(order) > 6` guard's replacement: a shared cell can legitimately hold more
   players than a lone backup can, so the guard must count cells, not people.

Until then, `depth.html` and `matchup.html` should be read as *an* ordering the club printed
at some point before 2026-11-14, not as the club's current depth or as a faithful rendering
of its shared slots.
